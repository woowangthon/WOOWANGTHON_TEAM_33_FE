# 요구사항 보존 평가 기준

모든 사례는 합성이다. 현재 정답 후보는 구현 담당 AI가 작성했으며, 프롬프트 작성에 참여하지 않은 팀원의 독립 검수가 아직 필요하다. 결과는 잠정 평가이며 현장 성능이나 사람 검수 결과로 표현하지 않는다.

- 하나의 요구는 별도의 답변 또는 조치 판단이 가능한 최소 단위다. 수거·재발 방지·일정 문의는 세 요구다. 동일 요구의 반복은 하나로 합친다.
- 사실, 감정, 욕설만 있는 구간은 요구로 세지 않는다. 위협이나 성적인 요구를 정상 행정 요구로 바꾸어 포함하지 않는다.
- 명시적으로 요구한 불가능한 조치도 정답 요구에 포함한다. 적절한 거절 사유를 설명한 답변은 누락이 아니다.
- 각 정답에 원문 위치(source)와 연속된 원문 발췌(quote)를 기록한다. 원문에 없는 요구는 추가하지 않는다.
- 1단계는 원문 요구가 중립 요약 또는 요구 목록에 보존됐는지 검사한다. 짧은 요약문에 없더라도 명시적 요구 목록에 정확히 있으면 보존으로 인정한다. 의미 변경은 왜곡이다.
- 2단계는 답변됨 / 처리 불가 사유 안내 / 추가 확인 요청 / 누락·불충분으로 판정한다. '검토하겠습니다'라는 일반적 약속만으로 일정·이유·결과 문의에 답했다고 보지 않는다.
- 추가 확인은 그 요구를 처리하기 위해 필요한 구체적 정보 질문이어야 한다. 이미 원문에 제공된 정보를 다시 묻거나 관계없는 질문은 인정하지 않는다.
- 답변 대응 여부와 실제 처리 완료 여부를 구분한다. 법령 근거의 적합성도 별도 축이다.
- 업무 비판, 정식 이의 제기·소송·정보공개 예고를 폭언·신체 위협으로 단정하지 않는다.

팀원은 complaints-40.json의 expectedRequests와 expectedExpression을 검수하고 labelStatus를 human_reviewed로 바꾼 뒤 이름 대신 검수자 식별자와 날짜를 별도 기록한다. 견해가 다르면 먼저 기준을 합의한다. 평가 후 불리한 사례를 삭제하지 않는다.

재현 순서:

1. `node --env-file=.env.local evals/run-baseline.cjs`
2. `node --env-file=.env.local evals/run-evaluation.cjs`
3. `node --env-file=.env.local evals/finalize-evaluation.cjs`
4. `node evals/render-results.cjs`

동일 baseline.json을 재사용한다. `build-dataset.cjs`는 최초 평가셋·기준 코드 보존용이므로 재측정할 때 실행하지 않는다. 독립 검수 이후 별도 실험을 시작한다면 기존 결과를 다른 디렉터리에 먼저 보관하고 실험 조건을 기록한다. 결과 HTML만 다시 만들 때는 4번만 실행한다.

3번은 필요한 추가 확인 요청을 누락으로 보던 자동 채점 기준을 명확히 하고, 요약·답변을 의도적으로 비운 별도 8건을 검사한다. 기존 탐지 결과와 초기 채점은 coverage-evaluation.json에 보존한다. 40건의 자연 발생 누락과 별도 주입 누락의 수치를 합치지 않는다. 이 실험은 자동 수정 후 정답률이 아니라 누락 탐지 결과를 측정한다.

서비스용 키는 기존 환경변수에서만 읽는다. 결과에는 합성 텍스트만 저장하고 키는 저장하지 않는다. 캐시가 없는 실행은 실제 API를 호출한다. 법령 검색의 전 분야 정확도와 직원 노출 감소는 이 평가의 측정 대상이 아니다.

## 2026-11-07 검사기 개선 평가

`run-coverage-v2.cjs`는 기존 40건의 입력·초안·추출 요구·참조 판정을 고정한 채 새 검사기와 1회 보완을 측정한다. 참조 판정은 개선 결과에 맞춰 수정하지 않는다. 새 결과 경로는 `COVERAGE_EVAL_OUT`으로 지정하며 입력/코드 해시가 바뀐 파일의 결과를 재사용하지 않는다. 마지막 실행과 남은 불일치는 `docs/COVERAGE-RESULTS.md`에 정리한다.

현장별 우회 경로·배출 장소·대기 장소는 위치에 따라 답이 달라질 수 있다. 일반적인 규정·기록 방법·상담 경로 안내를 위치 질문만으로 대신해서는 안 된다. 특정 서비스의 신청·수정 절차는 서비스 종류 자체가 없으면 식별 질문이 필요할 수 있다. 이런 경계는 사람 검수에서 요구의 실제 범위와 답변의 질문을 함께 읽어 판정한다.

근거가 부족하다는 구체적 설명은 대응 여부와 별개로 법적 타당성·유용성을 검토해야 한다. 단순히 누락 수가 줄었다는 이유로 민원이 해결됐다고 평가하지 않는다. 이번 개발셋과 경계 사례 12건은 개선 과정에 사용했으므로 미사용 평가셋으로 표현하지 않는다.

추가 회귀 검사: `node --env-file=.env.local evals/review-regression.cjs`는 일반적인 접수 확인·정보 부족 안내를 법적 근거 부족으로 오인하지 않는지, 실제 처리 완료·특정 일정 약속·제재 주장은 계속 검토 대상으로 남는지 실제 모델로 검사한다. 40건 평가는 수정하지 않는다.
