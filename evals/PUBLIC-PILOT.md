# 실제 공개 민원·표현 경계 사례 평가

이 평가는 민원쉴드의 **텍스트 표현 판별과 요구 추출**을 측정한다. 법령 검색, 법률 해석, 답변 정확성, 실제 처리 완료율, 음성 인식은 측정하지 않는다.

## 고정 입력과 참조 라벨

- 실제 공개 민원: 국토안전관리원 2025년 공개 자료에서 중복을 제외한 715건 중 검토 시작용 100건을 구성하고, 그 안에서 24건을 선택했다. 최초 선택 시 본문 160~1,000자, 서로 다른 분류를 우선하는 편의 표본이다. 무작위 현장 표본이 아니다.
- 합성 사례: 이번 평가를 위해 만든 40건. 직접 욕설 8, 띄어쓰기·초성·숫자 변형 6, 인신공격 6, 위협 4, 성적 모욕 2, 정당한 항의 8, 동음어·일반 대조군 6.
- 실제 24건에 참조 요구 54개, 합성 40건에 80개. 반복 요구는 통합하고 독립적으로 답변 가능한 요구를 분리했다.
- 참조 라벨은 모델 실행 전에 작성한 **AI 보조 초안**이다. 팀원의 독립 검수는 미완료다. 공개 기관 답변을 정답으로 취급하거나 모델 입력으로 보내지 않았다.
- 고정 통합 입력 SHA-256: `6cb6fd72e4b6eba62b2aaffa521d2da6746c5f34d2ebab3cfc67ca2a5150c4ef`.
- 실제 공개 출처: <https://www.data.go.kr/data/15124807/fileData.do>. 원 민원과 평가용 입력·출력은 로컬 연구 폴더에 보관하며 Git에 넣지 않는다. 합성 입력은 [public-pilot-synthetic-40.json](public-pilot-synthetic-40.json)에 별도로 보관한다.

실제 자료는 평가 전에 자동 마스킹과 AI 보조 식별정보 점검을 했다. 선택 사례의 사업장 상호·주소, 소속·이름, 제품 URL을 추가 가렸다. 사람의 개인정보 검수를 완료했다고 표현하지 않는다.

## 측정 경로

`lib/ai.ts`의 현재 `generateAnalysis` → `lib/coverage-ai.ts`의 별도 `auditRequirements` 호출 → 별도 의미 채점 호출.

초기 분석과 요구 재검사는 기존 서비스 함수를 그대로 사용한다. 법령 검색은 빈 근거 배열로 고정하여 평가에서 제외한다. 현재 승인된 서비스 모델 `gpt-6-luna`, 기본 추론 설정을 사용하고, 평가 중 서비스 프롬프트·정규식·추출 코드를 수정하지 않는다. 기준 코드 커밋은 `f76e7d0e5267832d7cda8e6fd72a85c18e65ff11`이며 파일별 해시를 실행 기록에 남긴다.

모델이 만든 욕설·비난 분류와 코드 후처리를 거친 최종 서비스 결과를 모두 저장한다. 이 둘의 차이는 후처리 진단에 사용한다. 서로 다른 모델을 독립적으로 비교한 실험은 아니다.

정답 요구와 기대 분류는 분석·재검사 호출에 전달하지 않는다. 의미 채점 호출에만 정답 요구와 생성된 요구 목록을 전달한다. **채점도 같은 모델 계열을 사용하므로 사람 검수를 대체하지 않는다.** 점수가 좋지 않은 사례도 삭제하지 않는다.

## 지표 정의

| 지표 | 분자 / 분모 |
|---|---|
| 보호 대상 표현 재현율 | 욕설·인신공격·위협·성적 모욕이 있는 참조 사례 중 최종 보호 경고가 뜬 수 / 해당 참조 사례 전체 |
| 보호 경고 정밀도 | 경고가 뜬 사례 중 참조 보호 대상인 수 / 경고가 뜬 전체 수 |
| 정상·정당한 항의 오경보 | 참조 보호 대상이 아닌데 경고가 뜬 수 / 결과가 있는 참조 정상 사례 수 |
| 유형별 재현율 | 그 유형을 주된 기대 분류로 지정한 사례 중 해당 유형이 나온 수 / 그 유형 기대 사례 수. 추가로 타당한 중첩 유형이 있을 수 있어 유형별 정밀도로 해석하지 않음 |
| 요구 보존율 | 핵심·대상·부정·조건이 모두 보존된 참조 요구 수 / 참조 요구 전체. 초기 목록과 별도 검사 목록을 따로 집계 |
| 원문에 없는 추가 요구 | 원문에서 요청하지 않은 조치·조건을 새로 요구로 추가했다고 잠정 채점된 수 / 생성 요구 수 |
| 표현 근거 인용 일치 | 표현 인용이 지정된 제목·본문에 실제 존재하는 수 / 최종 표현 인용 수. 의미 정확성과 별개 |

요구는 `preserved / partial / missing / distorted`로 구분한다. 부분 보존은 완전 보존으로 세지 않는다. 여러 참조 요구가 한 생성 문장에 정확히 표현되면 모두 보존으로 인정한다. 본문 밖의 요약이나 다른 검사 단계로 해당 목록의 누락을 메우지 않는다.

실행 실패와 채점 실패는 따로 기록한다. 채점 불가 요구는 `ungraded`로 남기며 전체 분모에서 없애지 않는다. 보고서에는 평가 완료 범위와 전체 분모를 함께 표시한다. 실제 자료에는 공격적인 참조 사례가 없어 그 자료로 공격 탐지 재현율을 계산할 수 없다.

## 채점 오류 처리

채점자의 요구 ID 중복·누락, 존재하지 않는 생성 요청 번호, 원문 또는 생성문에 없는 인용은 코드가 거부한다. 기술적으로 잘못된 채점에 한해 같은 입력으로 다시 채점할 수 있다. 생성 결과를 골라서 재실행하지 않는다. 최초 실행 기록을 별도 저장해 재시도 수와 원인을 공개한다.

이번 실행은 최초 채점 인용 오류 8건을 1회 재시도했다. 그중 6건이 통과했고, 남은 2건은 원문·참조 요구·생성 목록을 AI 보조로 대조해 별도 기록했다. 최종 의미 채점은 API 자동 채점 62건 + AI 보조 재검토 2건이며 독립 사람 검수는 0건이다. 서비스 요구 재검사 실패 2건은 재실행하지 않고 실패 상태와 참조 요구 4개를 그대로 분모에 남겼다.

## 재현

프로젝트 폴더에서 승인된 기존 환경 파일을 사용한다. 실제 API 비용이 발생한다. 결과 경로는 로컬 연구 폴더 또는 Git에서 제외된 `outputs/`로 지정한다.

```powershell
node --env-file=.env.local evals/run-public-pilot.cjs <검토한-dataset.json> <로컬-run.json>
node evals/public-pilot-metrics.cjs <같은-dataset.json> <로컬-run.json> <로컬-metrics.json>
node --test tests/public-pilot-metrics.test.cjs
```

실행기는 기존 성공 사례를 재사용하고, 데이터·모델·서비스 코드 해시가 바뀌면 같은 결과 파일에 이어 쓰지 않는다. 외부 요청은 OpenAI Responses API로 제한하고 `store:false`를 확인한다. 서비스 DB에 민원을 넣거나 사이트에 게시하지 않는다. 호출 수 220회, 관측 누적 토큰 700,000 초과 시 후속 호출을 중단한다. 이미 진행 중인 요청은 있어 한계가 정확한 청구 상한을 보장하지는 않는다.

성능 수치는 [결과 보고서](../docs/PUBLIC-PILOT-RESULTS.md)에 기록한다. 이 수치를 현장 정확도, 독립 사람 평가, 법령 정확도 또는 서비스 전체 정확도로 표현하지 않는다.

저장된 실행 JSON의 집계는 재현할 수 있다. 모델을 다시 호출하면 비결정성·서비스 모델 갱신 등으로 출력과 점수가 달라질 수 있으므로 새 실행은 기존 결과를 덮어쓰지 않고 별도 버전으로 보관한다.
