# 민원사이 통화 지연 측정 · 2026-11-15

실제 Gemini API에 라이선스가 확인된 문장을 읽은 TTS 음원 3개를 전송했다. 로컬 WebSocket 중계에서 측정했으며 사람의 마이크·스피커, 브라우저 오디오 재생, 운영 사이트의 인터넷 왕복 시간은 포함하지 않는다. 아래 수치는 이 실행의 관측값이며 평균 응답 시간이나 보장 시간으로 일반화할 수 없다.

음성 인식은 `gemini-3.5-transcribe-live`, 판정·내용 정리는 `gemini-3.5-flash-lite`다. 민원인 → 담당자 음성 버퍼는 2.5초이며 담당자 → 민원인 음성은 즉시 중계한다.

| 측정 항목 | 일반 민원 | 직접 공격 표현 | 제3자 관련 표현 |
| --- | ---: | ---: | ---: |
| 입력 음원 길이 | 4.390초 | 8.205초 | 5.690초 |
| 음원 시작 → 첫 중간 전사 | 0.955초 | 0.745초 | 1.190초 |
| 음원 시작 → 담당자 소켓의 첫 음성 패킷 | 2.513초 | 2.524초 | 2.529초 |
| 음원 시작 → 첫 정리 텍스트 생성 | 5.580초 | 업무 사실 없음 | 업무 사실 없음 |
| 음원 시작 → 마지막 정리 텍스트 생성 | 7.360초 | 업무 사실 없음 | 업무 사실 없음 |
| 음원 끝 → 마지막 정리 텍스트 생성 | 2.970초 | 해당 없음 | 해당 없음 |
| 마지막 확정 전사 → 마지막 정리 텍스트 생성 | 2.220초 | 해당 없음 | 해당 없음 |
| 음원 시작 → 자동 차단 신호 | 차단 없음 | 6.364초 | 차단 없음 |

성공한 안전 판정 요청 19개의 소요 시간은 중앙값 1.114초, 범위 0.809~1.302초였다. 부분 전사 판정과 최종 발화 정리가 병렬로 실행되므로 이 시간들을 단순히 더한 값이 전체 통화 지연은 아니다.

직접 공격의 6.364초는 **음원 재생 시작부터** 잰 값이다. 욕설 단어 자체의 시작 시점이나 최초 공격 표현부터의 지연은 별도로 표기하지 않았다. 음원에는 공격 표현 이전의 발화도 포함되어 있다. 2.5초 음성 버퍼는 첫 욕설 전체 차단을 보장하지 않으며, 이전 검토에서 차단 신호 전 일부 공격 표현이 전달된 사례가 있었다. 이번 결과가 그 문제를 해결했다는 뜻은 아니다.

세 음원 모두 기대한 차단 여부와 분석 오류 없음 검사를 통과했다. 직접 공격 사례는 차단 신호 이후 추가 음성 패킷이 전달되지 않았고, 담당자 → 민원인 방향은 유지됐다. 실제 통화 품질·정확도 전체를 입증하는 평가가 아니다.

## 출처와 실행

- 일반 민원: [한국남동발전 환경관련 민원사항 현황](https://www.data.go.kr/data/15093026/fileData.do)의 KOEN-004. 공개 데이터에 표시된 이용허락범위 제한 없음 조건으로 수집한 기관 정리 문장을 사용했다.
- 공격·제3자 표현: [2runo/Curse-detection-data](https://github.com/2runo/Curse-detection-data/tree/ff241621e103b6f220d30de324d0d07987887308), MIT. 커뮤니티 문장이며 실제 민원 통화 녹음이 아니다. 원본 문장을 수정하거나 욕설을 추가하지 않았다.
- 음성: Microsoft Heami Desktop TTS. 원본·해시·라이선스 사본·상세 결과는 Git 밖 검토 폴더에 보관한다.
- 실행: `node --env-file=.env.phone-comparison.local scripts/verify-buffered-phone.mjs --live --sample=normal,attack,thirdparty`
- 상세 로컬 결과: `buffered-phone-1794681875643.json`. 이 파일의 원문과 음성은 저장소에 포함하지 않는다.
- 변경 범위: 측정 항목을 추가했으며 판정 정책·모델·2.5초 버퍼를 바꾸지 않았다. 측정은 운영 민원을 생성하지 않았다.
