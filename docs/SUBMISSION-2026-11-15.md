# 민원사이 · 제출 전 구현과 검증

## 구현

접수 → 원문 저장 → 사실·요청 추출 → 공식 법령 검색 → OpenAI 요약·초안 생성 → 요약 검증 → 답변의 요청별 대응 검증 → 결과 저장 → DB NOTIFY / SSE → 담당자 검토·승인 → 민원인 조회.

OpenAI 생성에 추출 사실이 전달됨을 테스트로 확인했다. 답변은 실제 문단 P ID와 원문 요청 R ID를 연결하고 모든 요청에 구체적 답변·사유·필요 정보 질문이 있는지 독립 모델과 코드가 검사한다. 빈 검토 약속은 통과하지 않는다. 보완은 1회이며 재검증 후 저장한다. 수정된 초안의 인용 목록도 갱신한다. 담당자가 나중에 수정한 초안까지 AI 검증을 통과했다고 표시하지 않는다.

단계별 체크포인트·원문 해시·초안 해시·재시도 기록을 저장한다. 실패한 민원도 목록에 남고 원문 확인·재시도가 가능하다. 크레딧 부족은 상세 화면의 큰 오류 패널에 표시한다. 요청 목록·검사 도구 화면과 완료 알림은 추가하지 않는다. 기존 파란색과 민원사이 이름을 유지한다.

공개 데이터는 ID와 원문을 대조한 뒤 출처·허락·원본 날짜·CSV 해시를 저장한다. 자료에 없는 위치·발생일은 만들지 않는다. 기관 처리내용은 생성 입력에서 제외한다.

## 공개 자료 평가

[한국남동발전 환경관련 민원사항 현황](https://www.data.go.kr/data/15093026/fileData.do) 13건은 이용허락범위 제한 없음이다. 기관이 정리한 짧은 민원내용이며 시민 전체 원문·통화 녹음은 아니다. 실제 OpenAI 호출 결과 12건이 내부 검증을 통과했고, 1건(지역주민 고충)은 구체적 사실이 없어 실패했다. 추가 진단에서도 사실 목록이 비어 실패했고 사례별 예외를 만들지 않았다. 이 독립 평가에서는 법령 검색을 제외했다. 내부 검증 결과를 독립 정확도로 해석하지 않는다.

욕설 검증은 별도 [2runo 커뮤니티 댓글](https://github.com/2runo/Curse-detection-data) 자료(MIT, Copyright 2020 2runo)를 사용했다. 이를 실제 민원이라고 표시하지 않는다. 기존 지자체 게시판 검토 자료는 이번 공개 시연 입력에서 제외한다.

## 통화 검증

Gemini 중계는 확정 전사와 판정을 마친 안전 구간만 재생한다. 미확정·불명확·실패 구간은 시간 초과만으로 풀리지 않는다. 보호 전환·재개 시 대기 음성을 지우고 담당자→민원인 음성은 유지한다. 종료 후 내용·위치·발생일을 담당자가 확인하여 접수한다.

다음은 원문을 수정하지 않고 Windows TTS로 읽은 3개 합성 음원과 실제 Gemini 호출 결과다. 실제 사람의 녹음이 아니며 마이크·스피커 하드웨어·일반 전화망은 검사하지 않았다.

| 입력 | 첫 중간 전사 | 첫 담당자 음성 | 보호 신호 | 결과 |
| --- | ---: | ---: | ---: | --- |
| 공개 민원 4.390초 | 0.912초 | 4.324초 | 없음 | 승인 구간만 전달 |
| 직접 공격 댓글 8.205초 | 0.709초 | 전달 없음 | 6.220초 | 담당자 음성 0프레임 |
| 제3자 발언 5.690초 | 1.213초 | 7.255초 | 없음 | 직접 공격으로 차단하지 않음 |

시간은 각 음원 전송 시작 기준 단일 관측값이며 공격 단어 시작 기준이나 평균이 아니다. 모든 전달 프레임의 승인 범위·차단 후 프레임 없음·담당자 음성 유지 검사가 통과했다. 확정 판정 대기로 지연과 구간 경계 누락이 생길 수 있다. 모든 공격의 완전 차단을 증명하지 않는다.

현재 음성 서버는 사용자 PC와 Cloudflare 터널에 의존한다. 웹 배포 성공을 상시 음성 서비스 배포 성공으로 표현하지 않는다. 원본 실행 기록은 저장소 밖 로컬 검증 폴더에 보관한다. 소스·자료·검증 보고서와 실제 최종 제출(hub·폼·발표·영상)은 별도다.

## 운영 주소 종단 검증

- 자동 테스트 **278개 통과**, TypeScript 검사·배포 빌드 통과.
- 공식 데이터 13건을 실제 시민 접수 API로 등록했다. Workflow의 공식 법령 조회·생성·요약 검증·답변 검증까지 12건 완료, 사실이 부족한 1건 최종 실패. 별도 새로고침 없이 담당자 화면에 SSE로 반영됨을 확인했다.
- 공개 데이터 KOEN-004의 화면 후속 조치 체크·취소·구체적 이력 저장을 확인했다. 답변을 검토·승인한 뒤 시민 API의 답변·완료 상태·분석 비공개를 대조했다. 검증용 기록이며 실제 행정 처리가 아니다.
- 운영 사이트 티켓 → 공개 WSS → 실제 Gemini → 담당자/민원인 경로를 검사했다. 일반 음성·업무 사실, 자동 보호, 공격 음성 구간 미전달, 보호 중 후속 요청 보존, 담당자 음성, 원음 재개, 종료 검사 모두 통과했다. 재개 직전의 무음 접두 구간 때문에 승인 음성을 버리는 오류를 수정했고 이전 구간은 재생하지 않는 회귀 검사를 추가했다.
- 마지막 운영 통화 단일 관측: 수락 후 연결 0.404초, 일반 음원 종료 후 업무 텍스트 2.989초, 공격 음원 시작 후 보호 신호 4.451초, 보호 중 후속 음원 종료 후 텍스트 2.397초. 이 측정은 TTS 입력이며 기기 왕복이나 평균 지연이 아니다.
