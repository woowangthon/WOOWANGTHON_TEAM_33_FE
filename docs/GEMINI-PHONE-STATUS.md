# 통화 Gemini 전환 — 2026-11-15 운영 연결

**최신 변경:** 고정 2.5초 지연을 Gemini 경로에서 제거하고 확정 전사·안전 판정을 통과한 음성 구간만 전달하도록 구현했다. 일반·직접 공격·제3자 발언 3개 실제 API 시험이 통과했으며 공격 음원에서는 담당자 수신 음성이 0프레임이었다. [최신 측정과 한계](SUBMISSION-2026-11-15.md). 아래는 이전 전환 기록이며 “남은 통화 보호 검증”은 이전 시점의 상태다. 실제 사람의 기기 왕복은 여전히 미검증이다.

사용자가 통화 API를 Gemini로 바꾸도록 확정했다. 웹 민원의 요약·분석은 기존 OpenAI 경로를 유지한다.

- 음성 인식: `gemini-3.5-transcribe-live`, WebSocket, 한국어 16 kHz PCM16, 중간 전사와 확정 전사 구분.
- 욕설·위협 판정과 사실 정리: `gemini-3.5-flash-lite`, stateless Interactions API. 원문 근거와 공격 대상을 확인하며 서비스 오류 시 다른 공급자로 자동 대체하지 않는다.
- `.env.phone.local`의 두 공급자 설정과 실행 기본값을 `gemini`로 변경했다. 기존 키는 Git에서 제외된 설정에 유지한다.

## 확인한 범위

전화 테스트 83개가 통과했다. 사용자가 제공한 Gemini 키로 로컬 실제 WebSocket 중계 → Gemini 음성 인식 → Gemini 판정·정리 → 담당자 반환 경로를 일반 민원 1건으로 다시 확인했다. 첫 중간 전사는 음원 전송 후 882ms였고, 분석 오류 없이 민원 사실을 반환했다. 이는 단일 음원의 관측값이며 평균 지연·정확도를 의미하지 않는다.

사용 음원은 한국남동발전 공개 데이터 `KOEN-004`의 원문을 TTS로 읽은 자료다. 실제 민원 통화 녹음이 아니다. 원본·해시·개인 로컬 보고서 `buffered-phone-1794681419428.json`은 저장소 밖 검토 폴더에 보관한다. 출처와 이용 조건은 `evals/licensed-data/`를 따른다.

Gemini 중계를 별도 포트 4319에서 실행하고, 서명된 `/api/phone/runtime` 등록으로 운영 사이트의 통화 연결 주소를 전환했다. 새 터널의 외부 연결 준비 중 등록이 일시적으로 503을 반환했으며, 준비 후 재등록은 성공했다. 운영 담당자 사이트가 발급한 티켓이 새 주소를 가리키는지, 해당 티켓으로 WebSocket 인증이 되는지, 수신 대기 시 운영 `/api/phone`이 `online:true, available:true`를 반환하는지 확인했다. 검증용 연결은 종료했고 민원은 등록하지 않았다. 기존 중계 프로세스는 유지한다.

실행기는 `PHONE_PORT`를 지원한다. 기본값 4318은 기존 상태 폴더를 사용하고, 다른 포트는 `outputs/phone-runtime-<port>/`에 상태·로그를 분리한다. 등록 CLI도 같은 포트를 사용한다. 키와 환경파일은 Git에서 제외한다. 이 PC와 터널이 실행되는 동안 제공하는 연결이며 상시 서버 배포는 아니다.

## 남은 통화 보호 검증

Gemini 전환의 연결 확인과 욕설이 담당자에게 들리지 않는다는 검증은 구분한다. 이전 2.5초 고정 버퍼 실험에서 AI 차단 신호 전 첫 공격 표현 일부가 전달된 사례가 있었다. 따라서 고정 지연만으로 완전 차단을 주장할 수 없다. 검토된 음성 구간만 재생하는 처리와 공격·제3자 발언·통화 종료 검증이 남아 있다.

운영 통화의 공급자와 연결 주소만 전환했다. 웹 사이트 소스는 이번 전환에서 재배포하지 않았다. 실제 사람의 마이크·스피커 왕복과 공격 표현 전체 차단은 미검증이며, 공급자 연결 확인을 완전한 통화 보호 검증으로 표시하지 않는다.
