# 실제 공개 민원·합성 경계 사례 1차 평가

2026-11-10, 현재 서비스 코드 `f76e7d0`과 `gpt-6-luna`로 측정했다. 실제 공개 민원 24건과 새 합성 사례 40건을 구분했다. **AI 작성 참조 라벨과 동일 모델 계열의 의미 채점에 대한 잠정 결과이며 독립 사람 검수는 0건이다.**

## 표현 판별

| 측정 항목 | 결과 | 해석 |
|---|---:|---|
| 합성 공격 표현 탐지 | **26/26 (100%)** | 이 작은 합성 표본의 재현율 |
| 경고 정밀도 | **26/28 (92.9%)** | 경고 28건 중 참조 보호 대상은 26건 |
| 합성 정상·정당한 항의 오경보 | **2/14 (14.3%)** | 동음어 2건을 욕설로 잘못 처리 |
| 합성 정당한 항의 오경보 | **0/8** | 감사·소송·언론 제보 예고 등을 공격으로 경고하지 않음 |
| 실제 공개 민원 오경보 | **0/24** | 이 표본에는 공격 표현 참조 사례가 없어 실제 욕설 재현율은 계산 불가 |
| 업무 비판·불만 태그 탐지 | **10/11** | 비판 라벨이 있는 실제 3건+합성 8건 중 태그 출력. 폭언 경고 여부와 별개 |

주된 유형별 탐지: 욕설 14/14, 인신공격 7/7, 위협 4/4, 성적 모욕 2/2. 한 사례가 복수 유형이므로 합이 26보다 크다. 추가로 타당한 유형이 있을 수 있어 이 수치를 유형별 정밀도로 해석하지 않는다.

### 코드 후처리의 이득과 부작용

같은 실행에서 모델 원출력은 공격 표현 25/26을 탐지하고 오경보 0/14였다. 최종 후처리는 띄어 쓴 욕설 1건을 보완했지만, **‘새끼 고양이’와 간지 ‘병신년’에 오경보 2건을 추가했다.**

`lib/protection.ts`가 문맥과 관계없이 `새끼`, `병신`을 욕설로 추가하면서 정상 판단을 `caution`으로 바꿨다. 새끼 고양이 사례에서는 요구 목록의 동물 표현도 가려졌다. 이는 실제 저장된 원출력·후처리 결과를 대조해 확인한 문제다. 평가 중 이 서비스 규칙은 바꾸지 않았다.

## 요구사항 추출

완전 보존은 핵심 행동·대상·부정·조건을 모두 유지한 경우다. 부분 보존은 성공으로 합산하지 않는다. 재검사 실패도 분모에서 제외하지 않는다.

| 자료·단계 | 완전 보존 / 전체 참조 요구 | 부분 보존 | 완전 누락·왜곡 | 검사 실패로 판정 불가 |
|---|---:|---:|---:|---:|
| 실제 24건 · 초기 요구 목록 | **52/54 (96.3%)** | 2 | 0 | 0 |
| 실제 24건 · 별도 요구 재검사 | **52/54 (96.3%)** | 2 | 0 | 0 |
| 합성 40건 · 초기 요구 목록 | **79/80 (98.8%)** | 1 | 0 | 0 |
| 합성 40건 · 별도 요구 재검사 | **75/80 (93.8%)** | 1 | 0 | **4** |

합성 재검사에서 결과가 나온 76개 요구만 보면 75/76이지만, 전체 80개 기준은 75/80이다. `syn-22`, `syn-39`는 요구 인용이 원문과 일치하지 않아 서비스 검증 단계에서 거부됐다. 이 두 입력의 모델 생성을 골라 재실행하지 않았다.

원문 밖의 추가·의미 변경으로 잠정 판정된 생성 요구는 실제 재검사 목록 1/70, 합성 초기 목록 1/82였다. 이 비율은 ‘정당한 행정 요구만 포함하는지’를 충분히 측정하지 않는다. **`syn-26`은 성적인 요구가 초기 행정 요구 목록에 섞였고, 별도 재검사에서 제외됐다.** 원문에 존재하는 요구라는 사실과 행정 요구로 받아들일 수 있다는 판단을 구분해야 한다.

조건 보존의 경계 판정도 남아 있다. 교육 대안의 의미, 자료 비교 대상, 예시 정보의 필수성, 우선 조치 순서 등이 부분 보존으로 판정됐다. 특히 예시 정보가 핵심 조건인지, 원인 조사에 결과 안내가 묵시적으로 포함되는지는 사람 검토가 필요하다. 잠정 채점 결과를 모두 확정된 제품 오류라고 단정하지 않는다.

## 먼저 고칠 항목

1. **문맥 없는 단어 강제 경고:** 동음어·정상 명사와 공격 표현을 구분하도록 규칙과 문맥 판정을 결합한다. 변형 욕설 탐지를 포기하거나 평가 사례별 정답을 하드코딩하는 방식은 피한다.
2. **요구 인용 불일치:** 원문 구간을 검증하고 기술적 인용 오류에 한해 1회 재추출한다. 실패를 성공 목록으로 대체하지 않는다.
3. **비행정적 공격 요구 혼입:** 성적인 요구·협박 자체와 그 주변의 정당한 민원 요구를 구분해 추출한다.
4. **조건 보존:** ‘먼저’, ‘안 되면’, ‘둘 중 어느 것이든’ 등 순서·조건·대안을 별도 확인한다. 참조 라벨의 모호한 기준도 먼저 사람이 검토한다.

## 실행 및 검증 기록

- 분석 응답 64/64, 서비스 요구 재검사 62/64. 최종 표현 인용 50/50이 지정 원문에 실제 존재했다. 인용 일치는 의미 정확도와 다르다.
- 초기 분석 호출 지연: 중앙값 5.97초, 95백분위 11.03초. 로컬 API 호출 기준이며 전체 접수·RAG·완료 시간은 아니다.
- API 200회, 입력 181,272토큰, 출력 109,454토큰, 합계 290,726토큰. 결제 금액은 조회하지 않았다.
- 최초 자동 의미 채점 인용 오류 8건 → 같은 생성 결과로 1회 재시도 → 6건 통과. 남은 2건은 원문과 생성 목록을 AI 보조로 대조했다. 최종 채점 방식은 API 자동 62건 + AI 보조 대조 2건이다.
- 최초 실행, 재시도 후 실행, AI 보조 대조 기록을 각각 보존했다. 데이터와 모델 생성 출력은 그대로 유지했다.
- 집계는 Node 구현과 별도 Python 계산으로 대조했다. 채점 누락·실행 실패 분모·부분 보존·중복 라벨 처리 검사 4개를 통과했다. 이 4개는 AI 성능 표본이 아니다.
- [평가 기준·재현 명령](../evals/PUBLIC-PILOT.md), [집계 결과 JSON](../evals/results/public-pilot-20261110-summary.json), [합성 입력 40건](../evals/public-pilot-synthetic-40.json).
- 실제 입력·출력과 검수 CSV는 로컬 연구 폴더 `data-research/real-complaints-20261110/evaluation-20261110/`에 보관한다. 실제 민원을 GitHub·공개 사이트·운영 DB에 넣지 않았다.

## 발표에서 쓸 문장

“실제 공개 민원 24건과 합성 경계 사례 40건으로 표현 판별과 요구 보존을 분리해 검사했습니다. 합성 공격 표현 26건을 모두 탐지했지만 정상 사례에서 동음어 오경보 2건이 있었고, 실제 민원의 요구 54개 중 52개가 완전히 보존됐다는 잠정 판정을 받았습니다. 원문 인용 검사 실패도 분모에서 제외하지 않았습니다. 현재 AI 작성 기준에 대한 개발 평가이며 독립 사람 검수를 진행해야 합니다.”

실제 자료는 시설·건설안전 전문 질의가 많고 편의 표본이다. 법령 검색·법률 해석·답변 정확도·현장 민원 해결률·음성 인식은 평가하지 않았다. 과거 합성 40건 평가와 데이터·측정 대상이 달라 성능 향상 전후 비교로 사용할 수 없다.
