# 발표용 검증 파트 · 7장

33팀 MIND · 2026-11-08. 기존 검증 발표자료를 갱신한 내용이다. 최종 제출용 전체 발표 PDF·영상과 구분한다.

## 1. 민원쉴드 — 요구 누락을 검사하는 규칙 하네스

공격적 표현을 가리면서 정당한 요구를 보존한다. 합성 민원 40건·100개 요구의 고정 답변으로 요구별 검사와 제한된 보완 효과를 측정했다.

## 2. 원문 계획 → 근거 추출 → 규칙 판정

원문만 보는 별도 호출에서 요구 종류와 원문 인용을 확정한다. 답변 검사와 보완 후 재검사에도 동일한 계획을 사용한다. 모델은 최종 status 대신 근거를 추출하고, 코드가 문장 ID·원문 인용·질문 범위·정보 종류·기존 제공 정보를 검사한다. 의미 추출의 오류까지 규칙으로 완전히 막는 것은 아니다.

인용 기술 오류는 최대 한 번 재추출하고, 누락 보완도 초안당 한 번으로 제한한다. 원래 문장을 유지하며 기존 대응이 퇴행한 보완을 거부한다. 답변이 바뀌면 법령 근거도 다시 검사한다.

## 3. 비교 조건

기존 답변·추출 요구·검색 조문·참조 판정을 고정했다. 제품 검사기와 보완기에 정답이나 평가 사례 ID를 보내지 않았다. 전체 40건을 새 API 호출로 검사하고, 보완한 답변은 기존 채점 지시문으로 별도 채점했다. 법령 검색·초안 생성부터 다시 실행한 실험은 아니다.

정답 후보는 AI 작성이며 동일 계열 모델로 채점했다. 개선에 사용한 개발 평가셋으로, 독립 사람 검수와 미사용 자료 검증은 남아 있다.

단위는 민원 건수가 아닌 요구사항이다. 사유 안내와 필수 정보 질문도 대응 있음에 포함하므로 민원 해결률이 아니다. 보완 후 답변됨 9, 사유 안내 13, 필수 질문 78, 누락 0개다.

코드 회귀 테스트 109개 통과. 기존 경계 12/12, 추가 의존 관계 8/8. 자동 테스트 수는 AI 정확도와 구분한다.

## 5. 문장 일부 발췌로 생긴 경고 수정

합성 회귀 테스트의 실제 답변은 “점검을 위해 정류장 번호를 알려 주세요.”이고, 인용은 “정류장 번호”다. 인용이 정확히 해당 문장에 존재하는지 확인한 다음 그 문장 전체에서 요청 표현을 확인한다. “정류장 번호는 별도로 관리됩니다.”에는 요청이 없어 질문으로 인정하지 않는다. 두 조건을 코드 테스트로 고정했다.

## 6. 남은 오류와 한계

- 보완 후 누락 0개, 고정 참조 대비 오경보 8개, 놓친 누락 0개.
- 직전 누락 4개 중 4개, 직전 오경보 8개 중 7개가 해소됐고, 새 오경보 7개가 발생했다.
- 보완한 답변의 전체 문장 중 13개는 법령 근거 재검토가 필요하다.
- 분류·근거 추출·참조 판정이 모두 틀릴 수 있다. 개별 불일치는 [전체 결과](COVERAGE-HARNESS-RESULTS.md)에 공개한다.

## 7. 재현과 다음 검증

입력·코드 SHA-256, 실제 API 사용량, 중간 실패 버전, 요구별 적용 규칙과 관찰값을 보존했다. 저장된 관찰값을 같은 코드에 통과시키는 [규칙 재실행 스크립트](../evals/replay-coverage-rules.cjs)는 API나 정답 없이 규칙 판정의 재현성을 검사한다. 이는 의미 정확성 검증을 대신하지 않는다.

## 추가 시연과 새 평가

시민 화면에서 요구 수정·추가·철회 → 담당자 화면에 같은 목록 표시 → 요구 하나에 추가 정보 요청 → 시민 답변 후 해당 요구만 재개 → 실제 처리 결과를 기록한 요구만 완료되는 흐름을 시연한다. 답변 완료와 현장 처리 완료를 구분한다.

기존 40건과 별개의 합성 12건을 실제 모델로 검사했다. 시민 수정 후 활성 요구 36개 유지, 철회 항목 재등장 0개, 고정된 요약 반영 기준과 36/36 일치했다. 작은 개발 평가이며 독립 사람 검수·법령 전체 정확도·민원 해결률을 뜻하지 않는다. 기존 오경보 8개가 해결됐다는 수치로 사용하지 않는다. [새 평가의 입력·조건·전체 결과](REQUEST-TRACKING-RESULTS.md).

운영 사이트에서도 별도 합성 민원 1건으로 위 흐름을 검증했다. 실제 AI·법령 조회·재분석이 끝난 뒤 활성 요구 3개, 처리 완료 1개, 진행 중 2개와 철회 이력이 유지됐다. 완료 기록은 합성 입력이며 실제 현장 처리 성과가 아니다. [실행 증거](../evals/results/request-tracking-live.json), [시민 화면](assets/request-tracking-citizen.jpg).

## 발표에서 설명할 구축 기여와 개선 효과

우리 팀은 원문 기준의 요구 검사 계획을 고정하고, AI가 추출한 답변 근거를 코드로 검증하는 하네스를 구축·개선했다. 인용 일치·요구와 질문의 관계·기존 제공 정보·보완 횟수·보완 후 퇴행을 검사하고, 적용 규칙과 실패 이력을 저장한다.

같은 모델을 사용한 고정 합성 40건·100요구 비교에서 **누락 여부의 참조 판정 일치율은 89%에서 92%로 3%p 상승**했다. 이전은 누락 탐지 15개와 정상 판정 74개, 현재는 누락 탐지 18개와 정상 판정 74개를 합산한 값이다. 보완 후 누락은 4개에서 0개로 감소했고, 오경보는 8개로 같았다.

발표 문장: “저희는 원문에서 요구사항을 먼저 고정하고, AI가 추출한 근거를 코드로 검증하는 하네스를 구축했습니다. 동일 모델과 고정 합성 평가에서 누락 여부의 참조 판정 일치율을 89%에서 92%로 높였고, 보완 후 남은 누락을 4개에서 0개로 줄였습니다.”

이 수치는 AI 작성 참조 판정에 대한 개발셋 일치율이다. 법률 해석이나 서비스 전체의 정확도를 의미하지 않으며 독립 사람 검수는 남아 있다. 규칙·프롬프트·호출 구조·추론 설정을 함께 바꾼 전후 비교이므로 개별 규칙 하나의 효과를 분리해 입증한 결과로 표현하지 않는다.
