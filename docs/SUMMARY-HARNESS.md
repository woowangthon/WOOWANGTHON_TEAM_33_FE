# 원문 근거와 발화 역할을 보존하는 요약 하네스

2026-11-15 · 하네스 정책 버전 5 · 로컬 검토본, 운영 미반영

## 실행 흐름

접수·원문 저장 → 원문 근거 추출과 검색 계획 → 원문 전체와 최초 요청 후보 대조·요청 정리 → 공식 법령 조회·일반 관련도 검색·AI 재선별 → 요약·내부 요청 목록·초안 생성 → 요약·요청 의미 검증 → 필요하면 한 번 재작성·재검증 → 계속 검증 실패하면 유효한 근거를 보존하고 자동 재생성 1회 → 검증된 결과 저장 → DB NOTIFY·SSE → 목록에 반영.

처리 중인 민원은 목록에서 숨기고, 완료된 민원과 최종 실패한 민원은 표시한다. 실패한 민원은 ‘AI 요약 실패 · 원문 확인 필요’로 표시하며 기존 상세의 원문 탭과 개별 재시도를 이용할 수 있다. 실패를 알리는 별도 일괄 배너·팝업은 추가하지 않는다. 분석 시작 버튼과 완료 안내 배너·토스트도 없다. 담당자 승인 후에만 답변을 공개한다. 사용자에게 요청사항 목록이나 검사 도구 화면을 추가하지 않는다.

## 사실과 요약 검증

- 검색 계획 호출에서 사실도 함께 추출한다. 문제, 실제 요청, 제3자에 의한 피해, 보호 요청, 장소·시점·수량을 구분한다. 특정 사례의 정답이나 욕설 단어를 프롬프트 예시로 넣지 않는다.
- 각 사실의 출처 필드와 연속 발췌를 코드가 확인하고 F1 등의 ID를 부여한다. 발췌가 실제 존재한다는 것은 의미가 참이라는 증명이 아니므로 다음 의미 검증에서 value도 원문과 대조한다.
- 발췌는 원문의 연속 문자열이어야 한다. 제안 발췌에 공백·줄바꿈 차이만 있고 원문에서 대응하는 구간이 유일하면, 그 원문 구간 자체를 복사하고 동일한 연속 문자열 검사로 확인한다. 제안 발췌와 복구 발췌는 기록한다. 여러 위치가 대응하거나 글자·괄호·내용이 다르면 추측하지 않고 실패한 항목 인덱스와 원문으로 AI 복구를 한 번 요청한다. 최초 사실 추출과 원문 요청 정리 각각에 적용하며, 계속 불일치하면 중단한다. 재작성한 사실도 같은 원문 구간 복구·정확한 발췌 검사로 확인한다. 특정 민원·욕설·법령 이름에 대한 예외나 고정 답변을 추가하지 않는다.
- 별도 요청 정리 호출은 원문 전체와 최초 요청 후보를 함께 대조한다. 정답·참조 라벨은 전달하지 않는다. 후보에 없는 요청도 찾고, 후보 각각의 보존·중복·실제 요청 아님을 최종 항목 인덱스와 이유로 기록한다. 코드가 모든 후보가 한 번씩 처리됐는지와 연결 인덱스가 유효한지 검사한다. 의미가 같은 요청의 중복은 AI가 판단하며 원문·후보·정리 결과를 추적할 수 있다. 불만을 강조하는 수사적 반문을 별도 행정 처리 요구로 만들지 않는다.
- 정리한 최초 원문 요청에 고정 R ID를 부여한다. 요약 재작성 과정에서 F 사실 ID가 바뀌어도 R 목록은 체크포인트에 보존한다. 매 검증의 `sourceCoverage`에서 모든 R ID가 실제 내부 요청 항목에 연결되고 질문 유형·대상·조건이 보존됐는지 검사한다. 사실 배열을 재작성하면서 요청을 삭제해 검증을 통과시키지 못한다.
- 요청 사실에는 `requestIntent`와 `conditions`를 기록한다. `action`, `explanation`, `rule_basis`, `confirmation`, `protection`을 구분하며, 제한의 법적 근거를 묻는 질문을 단순 가능 여부로 바꾸지 않는다. 직접 보호 조치 요청과 사과·조사·징계 같은 일반 처리 요구도 구분한다. 피해 사실 자체는 별도로 보존한다.
- 누락 판단에도 출처 필드·연속 발췌·발화 역할을 요구한다. 업무 사실·제3자 피해·보호 요청은 보존 대상으로 삼고, 담당자를 향한 직접 공격과 불필요한 자료 설명은 의도적 제외로 구분한다. 코드가 실제 직접 공격 발췌와 대조해 검증자가 공격을 업무 누락으로 다시 요구하는 것을 막는다.
- 별도 AI 호출이 요약 문장과 내부 요청 항목을 사실 ID에 연결하고, 원문에 없는 내용·핵심 업무 누락·공격 표현 재노출·잘못된 사실 추출을 검사한다. 요청 검사는 같은 호출에 포함하며 화면에 새 목록을 만들지 않는다.
- 요약은 핵심 문제와 필요한 장소·시점, 피해 사실과 보호 요청을 맡는다. 모든 일반 요청을 요약에 반복할 필요는 없다. 내부 requests 목록은 추출된 모든 requested_action과 protection_request를 보존한다.
- 코드는 검증한 문장·요청 항목이 실제 저장할 값과 같은지, 요청 항목의 인덱스가 중복·누락되지 않았는지, ID가 존재하는지, 핵심 사실과 피해·보호 요청의 요약 근거가 빠지지 않았는지 검사한다. 모든 추출 요청 ID가 내부 목록에 연결되어야 하며 의미 일치는 AI 검증으로 확인한다.
- 요청 검증자는 실제 생성 문구에서 다시 읽은 의도와 대상·조건 보존 여부를 연결 ID마다 기록한다. 코드가 추출된 원래 의도와 비교하므로 ID만 맞고 질문 유형이 다른 결과는 통과하지 않는다. 대상·조건 누락이나 검증 항목 누락도 실패다. 의미 판정 자체는 여전히 AI의 오류 가능성이 있다.
- 요약 검증은 사실성·공격 재현 여부와 별도로 각 문장의 `necessary`를 확인한다. 핵심 처리·피해·보호·접근 지원에 불필요한 개인 배경이 있으면 수정한다. 부차 경위의 누락은 핵심 업무 누락과 구분하며, 일반 요청 전체를 요약에 반복하도록 강제하지 않는다. 생성·검증·수정에 요약 필수 사실 ID를 전달한다.
- 요약·검색 계획·조문 선별·요약/요청 검증·사진 관찰은 OpenAI만 사용한다. 공급자 선택과 다른 공급자 호출 경로는 제거했다. OpenAI 생성에 추출 사실과 이전 검사 의견이 전달되는지 모의 전송 검사로 확인한다. 공통 프롬프트·응답 검증은 `lib/analysis-contract.ts`에 보존한다.
- 제3자의 폭언·협박 피해와 보호 요청은 보존한다. 민원인이 담당자에게 가한 공격 문구는 직접·간접 인용 모두 요약에 재현하지 않는다.
- 요약이나 내부 요청 목록이 잘못됐으면 검사 의견을 전달해 한 번 재작성하고 다시 검사한다. 사실 추출 자체에 오류·누락이 있으면 같은 수정 호출에서 원문 발췌와 함께 사실도 다시 추출한다.
- 검증이 계속 실패하면 앞선 검증 의견을 전달하여 자동으로 재생성을 한 번 시도한다. 유효한 계획·검색 근거는 재사용하고, 사실 추출 오류나 누락이 있으면 계획부터 다시 만든다. 이전 결과·검사 의견은 새로운 사실의 근거가 아니며 현재 원문과 다시 대조한다. 재생성 후에도 한 번의 수정·재검증을 허용하며 계속 실패하면 원문과 실패 기록을 보존하고 목록에서 개별 재시도를 제공한다. 조회·새로고침이 실패 건을 무한히 재실행하지 않는다.
- 재작성·자동 재생성 사용 횟수와 후보·검증·실패 이력을 체크포인트에 저장한다. 자동 재생성 준비는 중복 실행되어도 기록을 다시 지우지 않는다. 유료 재작성 요청의 응답이 불명확하게 끊긴 경우 같은 요청을 자동으로 재발행하지 않는다. 명시적인 복구 재시도는 새 처리 회차를 시작한다.
- 통과하지 못한 요약을 제목이나 고정 성공 문구로 대체하지 않는다. 검증 완료 없이 최종 완료 상태를 저장할 수 없다.

## 검색·전화의 고정 규칙 정리

- 웹 분석은 발화자·공격 대상·주변 연속 문맥·구체적 실행 의사를 구조화한다. 코드가 `direct_attack`, `reported_speech`, `third_party_attack`, `criticism`, `non_attack`, `unclear`를 정리한다. 제3자 피해 신고·제3자 대상 공격·실제 동물 지칭을 담당자 직접 공격과 구분한다. 업무 비판은 공격으로 올리지 않는다. 담당자에 대한 직접 공격이면서 구체적 위협 실행 의사가 확인된 경우에만 `threat`다. 불확실한 문맥을 확정 위협으로 올리지 않는다. 문맥 발췌에도 동일한 원문 구간 복구·정확한 문자열 검사를 적용하고 복구 제안을 남긴다. 여전히 불일치한 문맥에는 표현 판정만 한 번 복구하며 요약·초안은 바꾸지 않는다. 복구 후에도 불일치하면 실패하고, 복구의 네트워크 응답을 알 수 없으면 자동으로 반복하지 않는다. 원문 가림과 실제 공격 판정은 구분한다.

- 분야별 법령 사전·특정 조문 가산점·감점을 일반 검색 경로에서 제거했다. 원문 의미와 AI 검색어로 일반 키워드 점수를 계산하고, 공식 후보 안에서 AI가 조문을 재선별한다.
- 관할은 `SERVICE_JURISDICTION`으로 설정한다. 기본 시제품 관할은 청주시다. 이 값은 인증·접근 범위를 바꾸지 않는다.
- 전화의 단어 목록은 빠른 검사 실행 신호와 표시 가림에 사용한다. 완성된 발화는 목록 유무와 관계없이 AI 판정을 받는다. 최종 자동 보호는 직접 공격이라는 문맥 판정, 분류, 원문 발췌 일치에 따른다.
- 원음 재검토에도 동일한 문맥·발췌 검사를 적용한다. 모델이 불확실하다고 한 결과는 직접 공격으로 확정하지 않는다.
- 실제 AI 분류·발췌를 음성 중계 보호 기록에 전달한다. 수동 전환과 분석 오류에 따른 보호는 별도 출처로 남기며 가짜 위협 분류·발췌를 만들지 않는다.

## 설정과 비용

로컬 검토 수정본에서는 요약의 2문장·220자 제한을 제거했다. 고정된 분량에 맞추지 않고 필요한 업무 내용을 빠짐없이 간결하게 전달한다. 생성 프롬프트·검증·응답 스키마와 과거 결과의 표시 경로에도 요약 문장 수·글자 수 상한을 두지 않는다. AI 요청의 출력 토큰 한도와 타임아웃은 유지하며, 응답이 중단되면 완료된 요약으로 저장하지 않는다. 사용자가 별도로 지시한 공개 민원의 로컬 API 평가는 진행하며 운영 배포는 최종본 확정까지 보류한다.

`lib/harness-policy.ts`에 정책 버전, 사실 최대 16개, 각 원문 추출의 AI 발췌 복구 1회, 회차별 재작성 1회, 자동 재생성 1회, 검색 후보 24개·선별 8개·최소 점수를 공개한다. 이들은 모든 입력에 동일하게 적용되는 운영 정책이며 사례별 답안이 아니다. 전화 모델 ID는 환경변수로 지정할 수 있다.

서비스 연결은 `SERVICE_OPENAI_API_KEY`, 모델은 `SERVICE_OPENAI_MODEL`을 사용한다. 공급자 선택 환경변수는 사용하지 않는다. OpenAI 서비스 설정이 없으면 연결 오류로 남기며 다른 공급자로 전환하지 않는다.

새 일반 텍스트 민원은 정상 경로에서 계획·사실 추출 1회 + 원문 요청 정리 1회 + 조문 선별 최대 1회 + 분석 1회 + 요약·요청 검증 1회로 총 4~5회 AI를 호출한다. 기계적인 공백 정합 복구는 API를 호출하지 않는다. 사실·요청 추출의 AI 복구는 각각 최대 1회, 표현 문맥 복구는 분석 회차당 최대 1회이며 재작성과 재검증이 필요하면 2회가 추가된다. 자동 재생성까지 두 회차 모두 전체 계획·검색·각 발췌/문맥 복구와 수정을 거치면 최대 20회다. 과거 첨부사진 관찰이나 일시 장애 재시도, 사용자가 누른 새 재시도는 별도다. 사용자 결정에 따라 애플리케이션의 통합 금액 상한은 추가하지 않는다. 영속 비용 원장을 구현했다고 주장하지 않는다.

인증·모델 접근·잔액 부족 등 명확한 설정 오류는 Workflow의 일시 장애 재시도에서 제외한다. 일시 장애에는 기존 제한된 단계 재시도를 적용한다.

## 이전 결과와 검증 범위

새 하네스에서 검증된 요약에는 표시 시 문장 삭제·절단 필터를 적용하지 않는다. 과거 저장 결과는 자동 재생성하거나 검증 완료로 소급 표시하지 않는다. 기존 결과의 공격 표현 재노출을 막기 위한 과거 읽기 필터만 호환 경로로 남기며, 빈 요약을 제목으로 대체하는 동작은 제거했다.

담당자는 기존 민원 접근 범위 안에서 읽기 전용 `/api/complaints/:id/harness`로 성공·실패 검증 기록을 확인할 수 있다. 시민에게는 제공하지 않으며 화면에 새 도구를 추가하지 않는다.

단위 검사는 모의 응답으로 근거·ID·상태·재시도 횟수 계약을 검사한다. 실제 API를 사용한 합성 입력 검증과 구분한다. AI 검증자도 오판할 수 있으며, 발췌와 ID 검사는 의미 정확도를 완전히 증명하지 않는다. 개발 사례와 독립 평가 사례를 나누고 사람 검수를 추가하기 전에는 정확도 개선 수치를 주장하지 않는다. 과거 누락 검사 89%→92% 수치는 이번 요약 하네스의 성능이 아니다.

버전 3은 실제 공개 결정례 8건에 대해 유료 API 평가를 수행했고 7건의 요약 검증 통과·1건의 발췌 실패를 기록했다. 내부 검증을 통과한 결과에도 진술 주체 혼동 가능성이 남아 있었다. 이 결과와 이후 버전 4의 추가 공개 게시판 표본 결과를 구분한다. 이전 버전의 합성 사례 통과를 실제 공개 민원의 정확도로 사용하지 않는다.

버전 4의 추가 공개 게시판 3건은 API 18회로 자체 요약 검증을 모두 통과했다. 직접 욕설 1건은 감지했고 제3자 욕설 피해 1건도 구분했지만, 원문 대조에서 질문 의미 약화·요청 추출 누락·제3자 표현의 직접 공격 오분류와 불확실한 위협의 과도한 수준 판정이 발견되었다. 현재 검증은 이 오류들을 모두 걸러내지 못한다. 실제 실패 응답을 재생한 별도 시험에서 발췌 복구 1회와 동일한 코드 검사를 확인했으며, 새 전체 실행에서 발생한 복구처럼 표현하지 않는다. [수집·실행 방법과 관찰 결과](../evals/public-complaints/README.md).

현재 로컬 검토본은 모의 API·상태·화면 렌더링 검사 181개, 타입 검사, 직접 Next.js 빌드를 통과했다. 기존 검사에 더해 요청 후보 처리 기록, 재작성 중 고정 R ID 보존, 질문 유형·대상·조건 검사, 발화자·대상에 따른 판정 일치, 불확실한 위협 처리, 유일한 원문 공백 정합 복구와 모호한 복구 거절, 표현 문맥 복구의 종료를 검사한다. 단위 검사 통과를 실제 민원 전체의 정확도로 해석하지 않는다.

v5의 최신 실제 API 실행은 같은 공개 게시판 3건을 16회 호출로 검사해 모두 자체 검증을 통과했다. 분납 제한 근거 질의·낚시금지구역 질의를 보존했고, 제3자 발언과 공격 대상을 구분했다. 원문 공백 정합 복구 1건이 실제 사용되었다. 수정 중 앞선 17회·21회 실행의 실패도 별도 코드 해시와 함께 남겼다. 수사적 반문을 실제 질문으로 남기는 문제와 모호한 질문의 대상 해석은 여전히 추가 검토가 필요하다. 새 결과를 독립적인 사람 검수나 전체 성능 수치로 표현하지 않는다. 답변 초안의 문단별 요청 대응 검사는 이번 수정에 구현했다고 주장하지 않는다.

웹 배포와 별도 음성 중계 프로세스 배포는 다르다. 전화 변경은 중계 서버가 새 소스로 재시작되어야 적용된다.
