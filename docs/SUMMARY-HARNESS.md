# 원문 근거와 발화 역할을 보존하는 요약 하네스

2026-11-14 · 하네스 정책 버전 3 · 로컬 검토본, 운영 미반영

## 실행 흐름

접수·원문 저장 → 원문 근거 추출과 검색 계획 → 공식 법령 조회·일반 관련도 검색·AI 재선별 → 요약·내부 요청 목록·초안 생성 → 요약·요청 의미 검증 → 필요하면 한 번 재작성·재검증 → 계속 검증 실패하면 유효한 근거를 보존하고 자동 재생성 1회 → 검증된 결과 저장 → DB NOTIFY·SSE → 목록에 반영.

처리 중인 민원은 목록에서 숨기고, 완료된 민원과 최종 실패한 민원은 표시한다. 실패한 민원은 ‘AI 요약 실패 · 원문 확인 필요’로 표시하며 기존 상세의 원문 탭과 개별 재시도를 이용할 수 있다. 실패를 알리는 별도 일괄 배너·팝업은 추가하지 않는다. 분석 시작 버튼과 완료 안내 배너·토스트도 없다. 담당자 승인 후에만 답변을 공개한다. 사용자에게 요청사항 목록이나 검사 도구 화면을 추가하지 않는다.

## 사실과 요약 검증

- 검색 계획 호출에서 사실도 함께 추출한다. 문제, 실제 요청, 제3자에 의한 피해, 보호 요청, 장소·시점·수량을 구분한다. 특정 사례의 정답이나 욕설 단어를 프롬프트 예시로 넣지 않는다.
- 각 사실의 출처 필드와 연속 발췌를 코드가 확인하고 F1 등의 ID를 부여한다. 발췌가 실제 존재한다는 것은 의미가 참이라는 증명이 아니므로 다음 의미 검증에서 value도 원문과 대조한다.
- 누락 판단에도 출처 필드·연속 발췌·발화 역할을 요구한다. 업무 사실·제3자 피해·보호 요청은 보존 대상으로 삼고, 담당자를 향한 직접 공격과 불필요한 자료 설명은 의도적 제외로 구분한다. 코드가 실제 직접 공격 발췌와 대조해 검증자가 공격을 업무 누락으로 다시 요구하는 것을 막는다.
- 별도 AI 호출이 요약 문장과 내부 요청 항목을 사실 ID에 연결하고, 원문에 없는 내용·핵심 업무 누락·공격 표현 재노출·잘못된 사실 추출을 검사한다. 요청 검사는 같은 호출에 포함하며 화면에 새 목록을 만들지 않는다.
- 요약은 핵심 문제와 필요한 장소·시점, 피해 사실과 보호 요청을 맡는다. 모든 일반 요청을 요약에 반복할 필요는 없다. 내부 requests 목록은 추출된 모든 requested_action과 protection_request를 보존한다.
- 코드는 검증한 문장·요청 항목이 실제 저장할 값과 같은지, 요청 항목의 인덱스가 중복·누락되지 않았는지, ID가 존재하는지, 핵심 사실과 피해·보호 요청의 요약 근거가 빠지지 않았는지 검사한다. 모든 추출 요청 ID가 내부 목록에 연결되어야 하며 의미 일치는 AI 검증으로 확인한다.
- OpenAI 생성 경로에도 추출 사실을 전달한다. OpenAI와 Gemini가 같은 입력을 받는지 모의 전송 검사로 확인한다.
- 제3자의 폭언·협박 피해와 보호 요청은 보존한다. 민원인이 담당자에게 가한 공격 문구는 직접·간접 인용 모두 요약에 재현하지 않는다.
- 요약이나 내부 요청 목록이 잘못됐으면 검사 의견을 전달해 한 번 재작성하고 다시 검사한다. 사실 추출 자체에 오류·누락이 있으면 같은 수정 호출에서 원문 발췌와 함께 사실도 다시 추출한다.
- 검증이 계속 실패하면 앞선 검증 의견을 전달하여 자동으로 재생성을 한 번 시도한다. 유효한 계획·검색 근거는 재사용하고, 사실 추출 오류나 누락이 있으면 계획부터 다시 만든다. 이전 결과·검사 의견은 새로운 사실의 근거가 아니며 현재 원문과 다시 대조한다. 재생성 후에도 한 번의 수정·재검증을 허용하며 계속 실패하면 원문과 실패 기록을 보존하고 목록에서 개별 재시도를 제공한다. 조회·새로고침이 실패 건을 무한히 재실행하지 않는다.
- 재작성·자동 재생성 사용 횟수와 후보·검증·실패 이력을 체크포인트에 저장한다. 자동 재생성 준비는 중복 실행되어도 기록을 다시 지우지 않는다. 유료 재작성 요청의 응답이 불명확하게 끊긴 경우 같은 요청을 자동으로 재발행하지 않는다. 명시적인 복구 재시도는 새 처리 회차를 시작한다.
- 통과하지 못한 요약을 제목이나 고정 성공 문구로 대체하지 않는다. 검증 완료 없이 최종 완료 상태를 저장할 수 없다.

## 검색·전화의 고정 규칙 정리

- 웹 분석도 direct_attack·reported_speech·criticism·unclear로 발화 역할을 구분한다. 제3자 폭언 피해 신고는 직접 공격 경고에서 제외하며, 분석이 끝난 뒤 단어 목록으로 판정을 덮어쓰지 않는다. 원문 가림과 실제 공격 판정은 구분한다.

- 분야별 법령 사전·특정 조문 가산점·감점을 일반 검색 경로에서 제거했다. 원문 의미와 AI 검색어로 일반 키워드 점수를 계산하고, 공식 후보 안에서 AI가 조문을 재선별한다.
- 관할은 `SERVICE_JURISDICTION`으로 설정한다. 기본 시제품 관할은 청주시다. 이 값은 인증·접근 범위를 바꾸지 않는다.
- 전화의 단어 목록은 빠른 검사 실행 신호와 표시 가림에 사용한다. 완성된 발화는 목록 유무와 관계없이 AI 판정을 받는다. 최종 자동 보호는 직접 공격이라는 문맥 판정, 분류, 원문 발췌 일치에 따른다.
- 원음 재검토에도 동일한 문맥·발췌 검사를 적용한다. 모델이 불확실하다고 한 결과는 직접 공격으로 확정하지 않는다.
- 실제 AI 분류·발췌를 음성 중계 보호 기록에 전달한다. 수동 전환과 분석 오류에 따른 보호는 별도 출처로 남기며 가짜 위협 분류·발췌를 만들지 않는다.

## 설정과 비용

로컬 검토 수정본에서는 요약의 2문장·220자 제한을 제거했다. 고정된 분량에 맞추지 않고 필요한 업무 내용을 빠짐없이 간결하게 전달한다. 생성 프롬프트·검증·응답 스키마와 과거 결과의 표시 경로에도 요약 문장 수·글자 수 상한을 두지 않는다. AI 요청의 출력 토큰 한도와 타임아웃은 유지하며, 응답이 중단되면 완료된 요약으로 저장하지 않는다. 운영 배포와 실제 유료 API 검증은 최종본 확정 후 진행한다.

`lib/harness-policy.ts`에 정책 버전, 사실 최대 16개, 회차별 재작성 1회, 자동 재생성 1회, 검색 후보 24개·선별 8개·최소 점수를 공개한다. 이들은 모든 입력에 동일하게 적용되는 운영 정책이며 사례별 답안이 아니다. 전화 모델 ID는 환경변수로 지정할 수 있다.

새 일반 텍스트 민원은 정상 경로에서 계획·사실 추출 1회 + 조문 선별 최대 1회 + 분석 1회 + 요약·요청 검증 1회로 총 3~4회 AI를 호출한다. 재작성과 재검증이 필요하면 2회가 추가된다. 이후 자동 재생성까지 필요한 경우 유효한 근거 재사용 여부에 따라 호출이 추가되며, 두 회차 모두 전체 계획·검색과 수정까지 거치면 최대 12회다. 과거 첨부사진 관찰이나 일시 장애 재시도, 사용자가 누른 새 재시도는 별도다. 사용자 결정에 따라 애플리케이션의 통합 금액 상한은 추가하지 않는다. 영속 비용 원장을 구현했다고 주장하지 않는다.

인증·모델 접근·잔액 부족 등 명확한 설정 오류는 Workflow의 일시 장애 재시도에서 제외한다. 일시 장애에는 기존 제한된 단계 재시도를 적용한다.

## 이전 결과와 검증 범위

새 하네스에서 검증된 요약에는 표시 시 문장 삭제·절단 필터를 적용하지 않는다. 과거 저장 결과는 자동 재생성하거나 검증 완료로 소급 표시하지 않는다. 기존 결과의 공격 표현 재노출을 막기 위한 과거 읽기 필터만 호환 경로로 남기며, 빈 요약을 제목으로 대체하는 동작은 제거했다.

담당자는 기존 민원 접근 범위 안에서 읽기 전용 `/api/complaints/:id/harness`로 성공·실패 검증 기록을 확인할 수 있다. 시민에게는 제공하지 않으며 화면에 새 도구를 추가하지 않는다.

단위 검사는 모의 응답으로 근거·ID·상태·재시도 횟수 계약을 검사한다. 실제 API를 사용한 합성 입력 검증과 구분한다. AI 검증자도 오판할 수 있으며, 발췌와 ID 검사는 의미 정확도를 완전히 증명하지 않는다. 개발 사례와 독립 평가 사례를 나누고 사람 검수를 추가하기 전에는 정확도 개선 수치를 주장하지 않는다. 과거 누락 검사 89%→92% 수치는 이번 요약 하네스의 성능이 아니다.

버전 3의 실제 유료 API 검증과 운영 배포는 아직 수행하지 않았다. 이전 버전의 합성 사례 통과를 버전 3의 실측 결과로 사용하지 않는다.

현재 로컬 검토본은 모의 API·상태·화면 렌더링 검사 157개와 Next.js 빌드·타입 검사를 통과했다. 새 검사는 공급자 간 사실·검사 의견 전달, 내부 요청의 연결 누락·잘못된 ID·문구 변경, 자동 재생성의 종료·중복 실행·체크포인트 보존, 최종 실패 목록 표시와 개별 재시도 제공을 포함한다.

웹 배포와 별도 음성 중계 프로세스 배포는 다르다. 전화 변경은 중계 서버가 새 소스로 재시작되어야 적용된다.
