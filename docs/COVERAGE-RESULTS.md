# 요구 누락·오경보 개선 검증

2026-11-07 · gpt-6-luna · 합성 개발 평가. 정답 후보와 참조 판정은 AI 작성이며 독립적인 사람 검수는 아직 없다.

## 동일 답변의 검사기 비교

| 지표 | 기존 검사기 | 개선 검사기 |
| --- | ---: | ---: |
| 기존 답변의 누락 요구 | 18 | 18 |
| 누락 중 탐지 | 15/18 | 15/18 |
| 놓친 누락 | 3 | 3 |
| 참조 판정 대비 오경보 | 13/82 | 8/82 |
| 누락 탐지율 | 83.3% | 83.3% |
| 오경보율 | 15.9% | 9.8% |

단위는 민원 건수가 아니라 **요구사항 개수**다. 40건에 100개 요구가 있고, 고정 참조 판정은 18개를 누락, 82개를 대응 있음으로 분류한다. 이전 15건/18건, 오경보 13건이라는 표기는 요구사항 15개/18개, 13개로 읽어야 한다.

## 보완 후 답변 평가

- 누락으로 참조 판정된 요구: **18개 → 4개**.
- 보완 시도 15건, 채택 13건. 기존 초안을 유지한 채 한 번 추가하고 전체 요구를 재검사했다.
- 별도 채점에서 새로 누락된 것으로 분류된 요구: 0개.
- 보완 후 상태: 답변됨 12개, 사유 안내 10개, 필수 정보 질문 74개, 누락 4개.
- 경계 사례: 12/12건. 일반 안내와 현장 질문, 이미 제공된 정보, 막연한 약속, 입력 지시 공격 등을 점검했다.
- 보완한 답변 전체에서 근거 재검토가 필요한 문장 11개. 그중 기존 답변에 없던 추가 문장은 9개다. 검토 필요 문장이 있으면 자동 공개되지 않는다.

사유 안내·필수 정보 질문은 민원 해결이나 법률상 정당한 거절을 뜻하지 않는다. 법령 검색 성공률, 민원 해결률 또는 현장 정확도는 이번 지표가 아니다.

## 수정 내용

1. 개별 현장 조치와 일반적인 방법·기준·상담 경로 문의를 구분하고, 답변 전체의 공통 보완 질문을 요구별로 연결한다.
2. 제목·본문·시민 보완 답변뿐 아니라 위치·발생일·분류도 확인해 이미 준 정보를 다시 묻는 답변을 통과시키지 않는다.
3. 대응 문장 ID와 실제 연속된 인용문, 필요한 정보와 그 이유를 검증한다. 알 수 없는 문장이나 인용은 실패 처리한다.
4. 누락된 요구만 한 번 보완한다. 기존 문장은 보존하며, 새 조문 인용을 검증하고 전체 요구 및 문장별 법령 근거를 다시 검사한다.
5. 이전에 대응했던 요구를 놓치거나 누락 수가 줄지 않으면 보완안을 채택하지 않는다. 담당자 수정본은 기존 동시 수정 보호 규칙으로 보존한다.
6. 검사 버전 또는 민원 정보가 바뀌면 이전 승인용 검사 결과를 무효화한다.

## 측정 방법과 재현

- 고정 입력: [합성 40건](../evals/complaints-40.json), [기존 답변과 조문](../evals/results/baseline.json), [기존 추출 요구](../evals/results/coverage-evaluation.json), [고정 참조 판정](../evals/results/final-evaluation.json).
- 개선 측정: [전체 실행 결과](../evals/results/coverage-v2-evidence.json), [요약](../evals/results/coverage-v2-summary.json), [경계 사례](../evals/coverage-boundaries.json). 입력 및 검사기 코드의 SHA-256은 실행 결과 hashes에 있다.
- 검사기는 같은 gpt-6-luna 모델의 medium reasoning, 최대 출력 8,192토큰을 사용한다. 변경 전 검사기는 low reasoning이었다. 검사기와 보완기는 정답 라벨을 받지 않는다. 기존에 추출한 요구를 재사용해 검사·보완 효과를 분리 측정했다. 요구 추출부터 법령 검색·초안 생성까지 40건을 전부 새로 실행한 결과는 아니다.
- 보완된 답변만 기존 finalize-evaluation.cjs의 동일 채점 지시문으로 별도 API 호출했다. 변경 없는 답변은 고정 참조 판정을 재사용한다.
- 같은 모델 계열을 생성·검사·채점에 사용했다. 과거 검사 결과와 이번 결과는 호출 시점이 달라 비결정성 영향이 있을 수 있다.
- 첫 개발 실행 coverage-v2.json과 두 번째 coverage-v2-final.json도 보존했다. 두 번째 실행은 오경보가 14개로 늘어 채택하지 않았다. 일반 안내와 현장별 안내를 다시 구분하고 검사기의 reasoning effort를 low에서 medium으로 높여 전체 40건을 재실행했다. 보완 생성·별도 채점은 기존 low 설정이다. 최종 결과는 미사용 평가셋 성능이 아니다.
- 최종 실행 API 호출 117회, 입력 토큰 261,362, 출력 토큰 101,202. 실패 요청에는 사용량 집계가 없을 수 있다.

기존 결과를 덮어쓰지 않으려면 새 결과 경로를 지정한다. 입력·검사기 해시가 다르면 동일 결과 파일을 재사용하지 못한다. 캐시 없는 실행은 기존 서비스용 API 키로 유료 호출하며, 비밀값을 결과에 저장하지 않는다.

```powershell
$env:COVERAGE_EVAL_OUT='evals/results/coverage-v2-rerun.json'
node --env-file=.env.local evals/run-coverage-v2.cjs
node evals/render-coverage-v2.cjs evals/results/coverage-v2-rerun.json
```

## 무효 보완안의 처리와 원본 기록

실제 API 실행에서 2건(C05, C15)의 보완안이 검증에 실패했다. 이 오류를 성공 답변으로 바꾸거나 재호출해 좋은 결과로 교체하지 않았다. 원래 답변과 누락 판정을 그대로 유지하는 운영 코드의 결정적 fallback을 적용하고, 원래 답변의 고정 참조 판정으로 집계했다. 따라서 해당 요구가 누락이면 최종 누락에도 남는다.

- 원본 API 실행: [evals/results/coverage-v2-reviewed.json](../evals/results/coverage-v2-reviewed.json)
- 결정적 재집계: [finalize-coverage-rejections.cjs](../evals/finalize-coverage-rejections.cjs)
- 원본 오류는 각 사례의 repairError, 새 fallback 코드 해시는 reconciliation.fallbackSha256에 보존했다. API 실행 당시 코드 해시와 이후 fallback 코드 해시를 구분한다. 원본 40건의 모델 판정과 성공한 보완안은 교체하지 않았다.
- 보완안 검증 실패가 분석 전체를 실패시키지 않고 원본 초안·누락 경고를 보존하는 회귀 테스트를 추가했다. 웹·음성·기존 실험을 포함한 자동 테스트 **86개 통과**. 이는 실제 AI 품질과 별개다.

원본 오류를 같은 방식으로 재집계하려면:

```sh
node evals/finalize-coverage-rejections.cjs
node evals/render-coverage-v2.cjs
```

## 인용 기술 오류에 한정한 재검사

엄격한 인용 검증이 잘못 복사된 인용문을 차단하면서, 대응 내용이 실제로 있는 요구까지 누락 경고로 표시하는 문제가 있었다. 인용문 또는 문장 ID 검증 실패에만 독립적인 재판정을 **최대 1회** 추가했다. 재판정도 같은 인용 검증을 통과해야 하며 일반적인 의미상 누락에는 적용하지 않는다.

전체 40건의 저장된 1차 판정과 채택된 보완안 판정을 새 재검사 함수에 통과시켰다. 오류 조건에 해당한 C16의 3개 요구, C34의 1개 요구, C38 보완 후 1개 요구에서만 실제 API를 총 3회 호출했다. 나머지 입력·판정·정답·답변은 보존했다. 최초 오경보 12개 중 인용 문제 4개가 해소되어 **8개**가 남았다. 40건을 다시 생성한 실험으로 표현하지 않는다. 이전 경계 사례 12개에는 이 기술 오류가 없었고, 이번 변경은 별도 단위 테스트로 확인했다.

- [재검사 실행 스크립트](../evals/retry-coverage-evidence.cjs)
- 입력 기록과 해시, 변경 항목, 추가 API 사용량, 최종 코드 해시: 결과 JSON의 evidenceRetryReplay.
- 최종 웹·음성·기존 실험 자동 테스트 **89개 통과**, 프로덕션 TypeScript 및 빌드 확인.
- 새 전체 실행은 run-coverage-v2.cjs가 최초 검사부터 동일한 재검사 경로를 호출한다. 이번 보존 기록 재현은 finalize-coverage-rejections.cjs 다음 retry-coverage-evidence.cjs를 실행한 뒤 render-coverage-v2.cjs로 문서화한다.
