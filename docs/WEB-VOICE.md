# 웹 음성 상담

현재 로컬 검토본의 통화 기본 API는 Gemini다. 음성 인식·판정·정리의 실제 연결 확인 범위와 남은 보호 검증은 [Gemini 전환 상태](GEMINI-PHONE-STATUS.md)를 먼저 확인한다. 아래 과거 운영 검증과 현재 검토본을 혼동하지 않는다.

스마트폰 브라우저의 민원인과 PC 브라우저의 담당자가 중계 서버를 통해 통화한다. 전화번호 발급, 휴대전화 기본 전화 앱, PSTN 수발신은 사용하지 않는다. 발표 시 “웹 음성 상담 시제품이며 실제 전화망 연결은 향후 과제”라고 설명한다.

## 시연

1. 중계 PC에서 `node scripts/start-phone.mjs`를 실행하고 `Websites connected to this voice server.` 메시지를 확인한다.
2. 담당자 사이트 `/phone`에서 마이크를 허용하고 **수신 대기 시작**을 누른다.
3. 스마트폰의 민원인 사이트 `/phone`에서 분석 동의 후 **상담 연결**을 누른다. 상태 갱신에는 최대 약 15초가 걸릴 수 있다.
4. 담당자가 목록에서 **전화 받기**를 누른다. 실제 오디오 연결이 완료되면 통화 시간이 시작한다.
5. 보호 신호 이후 민원인 음성을 차단하고 정제 텍스트를 표시한다. 신호 전 첫 공격 표현의 전달을 막는 처리는 검증이 남아 있다. 담당자의 목소리는 계속 전달된다. 수동 보호/원음 복구 버튼도 사용할 수 있다.
6. 종료 후 정리된 요구를 검토하고 민원을 접수한다. 공개 시연 접수함에는 합성 자료만 사용한다.

가상 음원 버튼은 `/phone?demo=1`에서만 표시한다. 두 기기가 가까우면 이어폰을 사용해 피드백을 줄인다. 모바일 통화 중 페이지를 열어 두고, 기기가 오디오를 중단하면 **오디오 다시 켜기**를 누른다. 일반 전화의 수화부 자동 전환은 구현하지 않는다.

## 검증

- 단위/프로토콜: 웹 통화·필터·AudioWorklet 검사 27개 통과. 역할, 티켓 재사용, 연결 중 취소, 분석 장애, 음성 한도, 마지막 담당자 연결 해제, 끊긴 연결 정리를 포함한다.
- 기존 검사 96개 및 런타임 등록 인증 검사 1개 통과. 외부 DB나 실제 민원을 수정하는 통합 검사는 실행하지 않는다.
- 2026-11-14 실제 OpenAI 연결 및 합성 음원 검사: 연결, 일반 음성, 욕설 감지, 차단 후 분석 지속, 담당자 음성 전달, 전용 텍스트, 정상 종료 등 13개 검사 통과.
- 로컬 중계의 단일 측정: 연결 약 1.4초, 욕설 음원 시작부터 보호 약 5.7초, 일반 발화 종료부터 텍스트 약 9.3초. 평균이나 SLA가 아니며 첫 욕설이 전혀 들리지 않는다는 의미가 아니다.
- 실제 스마트폰 마이크/스피커, 모바일 브라우저 터치 조작은 별도 확인이 필요하다. 자동 프로토콜 검사는 하드웨어 검증을 대신하지 않는다.

## 2026-11-15 운영 음성 경로 점검

사용자가 통화 검증을 지시하여 현재 운영 두 사이트의 티켓·공개 WSS·실제 STT와 OpenAI 판정을 연결했다. 이용허락이 확인된 한국남동발전 민원 4·9행과 MIT 댓글 33행을 수정 없이 Windows TTS로 읽어 서로 다른 발화로 전송했다. 원래 시민이 통화한 녹음이 아니다.

연결, 정상 음성 전달·오차단 없음·요청 보존, 직접 욕설 자동 보호·재생 큐 정리·욕설 비재현, 보호 중 민원인 음성 차단·후속 요청 분석, 담당자 음성 전달 유지·정제 텍스트의 담당자 전용 전달, 원음 복구·요청 보존, 정상 종료·분석 오류 없음 등 16개 검사를 통과했다. 공격만 있는 발화에는 사실·요청을 만들어 넣지 않고 빈 facts를 반환했다.

단일 실행에서 받기→연결 약 1.5초, 정상 발화 끝→텍스트 약 3.5초, 욕설 음원 시작→차단 약 9.8초, 보호 중 후속 발화 끝→텍스트 약 2.2초였다. 욕설 음원 길이는 약 8.2초였다. 첫 욕설부터 즉시 차단하거나 평균 성능·최악 지연을 보장한다는 의미가 아니다. 실제 스마트폰 마이크·스피커와 브라우저 오디오 재생 장치는 검사하지 않았다.

재현: 먼저 `node evals/licensed-data/collect.cjs`, Windows에서 `powershell -File scripts/prepare-phone-licensed-audio.ps1`, 이어 `node scripts/verify-phone-licensed-flow.mjs --live`. 마지막 명령은 실제 운영 중계와 유료 API를 사용한다. 이미 담당자나 통화가 있으면 중단한다. 원본 음원·출처·결과는 저장소 밖 `../phone-licensed-check/`에 저장하고 원문·오디오를 Git에 넣지 않는다. 기대 단어는 검증 스크립트에만 있고 실제 모델 입력에 정답으로 전달하지 않는다.

## 운영 설정

### 실시간 판정

실시간 전사는 `gpt-live-transcribe`(delay=`low`), 완료 음성 재전사는 `gpt-transcribe`를 기본값으로 쓴다. 비어 있지 않은 새 전사는 단어 목록 없이 AI 문맥 판정에 보낸다. 통화당 부분 판정은 1개씩 실행하고 시작 간격은 기본 최소 1.2초다. 진행 중 델타는 최신 문장으로 합친다. 최종 음성 재확인과 업무 사실 검증은 별도로 진행하며 보호 판정이 요약을 기다리지 않는다. 세부 계측·한계는 `docs/PHONE-LATENCY.md` 참조.

업무 사실 후보는 원문 근거와 별도 AI 역할 검사를 통과해야 한다. 직접 공격을 순화한 문장은 업무 사실로 표시하지 않고, 제3자 피해 신고와 보호 요청은 보존한다. 표시용 욕설 마스킹은 판정용 단어 목록이 아니다.

### 연결과 정책

중계 키는 `.env.phone.local`, OpenAI 키는 `.env.local`에만 저장하며 Git에 포함하지 않는다. 웹사이트 두 프로젝트의 `PHONE_BRIDGE_SECRET`은 중계 서버와 일치해야 한다. 로컬 중계는 OpenAI 키만 필요하고 운영 DB 비밀번호는 요구하지 않는다. 런타임 등록 API는 HMAC 서명, 2분 유효 시간, HTTPS 호스트 제한, 리다이렉트 거부, 중계 상태 확인을 통과한 요청만 처리한다.

임시 터널과 PC는 시연용이며 상시 가동을 보장하지 않는다. 서버 재시작 후 새 주소는 자동 등록한다. 등록 실패 시 배포 설정을 확인하고 `node scripts/register-phone.mjs`를 실행한다. 전화망 이용료는 없지만 AI, 데이터, 호스팅 비용은 별도다. 10분/30분 제한은 금액 상한이 아니며 서버 재시작 시 하루 카운터가 초기화된다.
